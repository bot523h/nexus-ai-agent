## ۲) بازبینی صفر تا صد — چه چیزی واقعاً در این مخزن هست

### ۲.۱ خط محصول (Phases 0–5 — کامل و منتشرشده)
کنترل‌پلن/امنیت → محصول هسته → LLM محلی → روتینگ چندفراهم‌کننده (litellm) → استقرار scale-to-zero (وبهوک تلگرام + Koyeb) → مدیریت اسکیما (Alembic + PostgreSQL/Neon) → ذخیره‌سازی پایدار (R2 blob tier + نگهداری زمان‌بندی‌شده). هر مرحله با PR، CI سبز و مدخل CHANGELOG تحویل شده است.

### ۲.۲ استودیوی نگار (Phase 6 — Nagar — در جریان)
- **ادغام‌شده در main:** موج ۱ (کاکپیت تایپ‌شده: `nagar.command.v1`، registry، bus)، موج ۲a (زیرساخت پک فقط-داده)، ۲b/۲c (پک اسلایدشو + لاین رندر FFmpeg تک‌پروسه‌ای با اثبات probe)، موج ۲.۵ (سطح تلگرام `/slideshow`)، موج ۳ (تولید تصویر `/imagine` با آداپتور Pollinations/Gemini و رضایت هزینه).
- **تحویل‌شده ولی «معلق» در runtime:** پک‌های edit (۸/۸)، motion (۵/۵)، audio (۴/۴)، delivery (۷/۷) و caption (۷ از ۱۰) ثبت شده‌اند ولی هیچ composition root آن‌ها را فعال نمی‌کند — خروجی واقعی `nexus packs list` این سشن: همه‌ی موارد بالا `pending`. فقط slideshow کاملاً فعال است.
- **در حال کار (عامل E، شاخه `arena/01a0c460`):** موج ۸ (لاین اعمال IR→filtergraph→FFmpeg)، موج ۹ (ASR محلی faster-whisper پشت `CaptionEnginePort`)، موج ۱۰ (درون‌سازی OTIO).

### ۲.۳ لایه‌بندی واقعی سورس (بررسی ساختاری)
```
application/ports/  → قراردادهای تایپ‌شده (hexagonal seam)     ✅ تمیز
domain/             → سیاست‌های خالص (retention/lifecycle)      ✅ تمیز، بدون import خارجی
adapters/ + storage/providers/ + llm/ + creative/*  → پیاده‌سازی‌ها
bot/                → سطح تلگرام (۲۰ ماژول؛ handlers.py با ۱۶۲۳ خط = گلوگاه نگهداری)
api/                → داشبورد FastAPI (HMAC + CORS + SSRF guard)
core/               → async_db، http_client با گارد SSRF/DNS-rebinding، instrumentation
creative/           → ۶ پک قابلیت فقط-داده + استودیو + لاین رندر
features/           → ۲۶ موتور محصول (برخی هنوز sync-DB؛ P1-2 چهار موتور بحرانی را با asyncio.to_thread اصلاح کرد)
```
۲۸ تست معماری (`tests/architecture/`) مرزهای import، فقط-داده بودن manifest پک‌ها، انزوای استودیو و امضای پورت‌ها را **به‌صورت خودکار قفل** کرده‌اند — این قوی‌ترین دارایی مهندسی مخزن است.

### ۲.۴ زیرساخت کیفیت
- CI دو-jobی: `test` (ruff → format → mypy → pytest) و `migrate-postgres` (Alembic واقعی روی PG16 + قرارداد آداپتور/لایف‌سایکل روی PG + اثبات idempotency).
- `maintenance.yml` زمان‌بندی‌شده (بکاپ R2 + housekeeping) با concurrency group و خروج non-zero در پیکربندی‌ناقص — «شکست پنهان ممنوع».
- ورک‌فلوی چندعاملی file-based (تخته‌ی claim با اجاره TTL، مرزبانی exclusive_paths، تک‌مالک گیت‌ها) — برای توسعه‌ی موازی سندباکس‌محور، الگوی درستی است و کار می‌کند.

## ۴) نقاط قوت مهندسی (با مدرک)

1. **انضباط گیت کیفیت واقعی و قابل‌اثبات** — سه گیت (lint/format/types) + تست ۹۹۰موردی + job مهاجرت روی PostgreSQL واقعی در CI؛ بازتولید محلی این سشن دقیقاً همین را تأیید کرد (990/20/0).
2. **تست معماری به‌جای توصیه‌ی معماری** — مرزهای import، فقط-داده بودن manifestها، امضای پورت‌ها و انزوای استودیو با ۲۸ فایل تست خودکار قفل شده‌اند؛ رگرسیون معماری را نمی‌توان بی‌صدا کامیت کرد.
3. **معماری hexagonal عملی، نه تشریفاتی** — پورت‌ها در `application/ports/` واقعاً رعایت می‌شوند؛ آداپتورهای SQLite/PG برای checkpoint/lifecycle پشت یک قرارداد مشترک با golden-fingerprint و reconciler و health-gate و kill-switch.
4. **امنیت به‌عنوان پیش‌فرض (deny-by-default)** — AccessGuard در group −1، گارد SSRF/DNS-rebinding در خروجی HTTP، redaction لاگ، HMAC داشبورد، gیت رضایت خروجی LLM (P0-7)، و ماتریس «Real vs Simulated» در README — صداقت وضعیت محصول در README خودش یک کنترل امنیتی فرایندی است.
5. **مونولیت مدولار با تصمیم مستند** — حذف Celery/Redis به نفع صف درون‌پروسه‌ای یک تصمیم ثبت‌شده (D-سری) است، نه فراموشی؛ «هیچ مهاجرت پنهان، هیچ جهش پنهان، هیچ تعمیر ضمنی» شعار اجرایی است.
6. **DECISION_LOG به‌عنوان منبع واحد حقیقت** — ۷۸۰ خط تصمیم با تاریخ، گزینه‌های ردشده و مدرک commit؛ رد تصمیم‌ها (Cognee، Real-ESRGAN، librosa، pgvector) هم ثبت شده — این سطح از نشخوار معماری در پروژه‌های این اندازه نادر است.
7. **لاین رندر مهندسی‌شده** — plan → IR خالص → filtergraph → argv → یک پروسه‌ی FFmpeg → probe اثبات‌شده، بدون shell، انتشار اتمی، بدون بازنویسی پیش‌فرض؛ و تست رندر واقعی با `imageio-ffmpeg` در dev-extra.
8. **CI دو سطحی عملیاتی** — جدا کردن گیت‌های push از maintenance زمان‌بندی‌شده، آف-ساعت کردن cron ها، concurrency group، و fail-loud روی پیکربندی ناموجود (R2) — جزئیات عملیاتی بالغ.
9. **استقرار چندسکویی واقعی** — Docker slim، Koyeb webhook scale-to-zero با healthz بدون touch دیتابیس، و مسیر Termux (الان تعمیرشده).
10. **هماهنگی چندعاملی file-based** — تخته‌ی اجاره با TTL/GC و مرزبانی مسیر، در محیط سندباکس‌های موازی عملاً از تداخل جلوگیری کرده (به‌جز موارد مستثنا که در بخش ضعف آمده).
