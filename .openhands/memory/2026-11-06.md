## Session (later) — live-main-cache fix completed; the P0's real root cause
- **Mission reframe:** the prior P0 fix (`48e02e24`/`617983fc`) proved ancestry against
  the LOCAL `origin/main` ref and keyed the 10-min cache by `(repo, number, sha,
  token-fp)` only. That left the *two confirmed defects*: (a) a stale/shallow clone's
  `origin/main` can be behind GitHub, so a positive verdict (fresh OR cached) can vouch
  for a merge GitHub has moved past; (b) the cache key omitted the live main SHA.
- **Fix (head `020d8b11`, pushed to `openhands/omni-recovery-integration-20261105`=PR#316):**
  - `_live_main_sha(repo, token)` → `GET /repos/{r}/git/ref/heads/main`, validated 40-hex,
    read on EVERY verification; its SHA is bound into the cache key → a moved main voids
    a warm cache and forces a re-proof.
  - `_github_ancestry_proven(repo, merge, live_main, token)` → `GET /compare/{m}...{main}`;
    accept only `status in {ahead,identical} AND behind_by == 0` (one combined guard — the
    two were mutually redundant, and splitting them left an unkillable mutant). Also
    require `ahead_by` an int ≥ 0.
  - `_verify_pr_merge(..., *, live_main=None)`; `_merge_still_verified` passes the SHA it
    already read, so cache key and proof use the SAME SHA (no TOCTOU window).
  - Fail-closed on: unreadable live ref, malformed/missing 40-hex sha, non-object
    response, diverged/behind compare, API outage. A warm cache never masks an outage
    because the live SHA is re-read before the cache is consulted.
- **Evidence:** 4 new trust-boundary tests RED on pre-fix code, GREEN after
  (`test_live_main_ref_is_read_on_every_verification_even_when_cached`,

  `test_stale_local_origin_main_cannot_vouch_for_a_moved_github_main`,
