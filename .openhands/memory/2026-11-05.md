## Gotchas learned
- A new creative ERROR_CODE requires a `creative.failed.<code>` key in ALL 15 locales
  (`tests/unit/test_creative_notify.py` is the lockstep gate) — same as input_integrity.
- Adding a test file that imports a creative operation drifts `OPERATION_TRUTH.json`
  (`tests/architecture/test_operation_truth_gate.py`) → regenerate with
  `python -m nexus_ai_agent.nagar --docs`.
- `model_copy(update={"assets": …})` BYPASSES the `state_hash` validator → recompute
  `compute_state_hash(project)` or the store's F1 read check rejects it.
- pytest has NO `--timeout` plugin here; run long suites with `nohup … &` + poll.
- InProcessJobQueue's background worker needs ONE event loop → use `@pytest.mark.asyncio`
  (asyncio_mode=auto), not repeated `asyncio.run`.

## CI lesson (trust-mutations minimal-deps)
`trust-mutations` pip-installs ONLY an explicit small set (no alembic, no chromadb/
flashrank/pypdf/arabic-reshaper/bidi). A suite run by a mutation harness MUST NOT
import `nexus_ai_agent.storage.migrations` (→ alembic). Bootstrap schema with
`asyncio.run(create_all_tables(path))` (the sibling durable suites do this).
Symptom: harness prints `baseline ... RED — refusing to mutate a suite that is
already failing` and exits 2. Reproduce locally by building a venv from the job's
exact pip line (see ci.yml trust-mutations step) — the main .venv hides it.
