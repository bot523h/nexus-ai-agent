## NEXUS-OMNI-PYTHON-MATRIX-CLOSURE-03 (session — PR #308 continuation)

**Root cause of the #308 3.10 failures**: `torch==2.15.0+cpu` has NO cp310 wheel.
PyTorch 2.15 dropped CPython 3.10; repo `requires-python=">=3.10"` and CI run a
3.10/3.11/3.12 parity matrix. **2.14.1 is the newest release with cp310/311/312
CPU wheels** (verified `GET https://download.pytorch.org/whl/cpu/torch/`).
Fix: `constraints/ci-cpu-torch.txt` → `torch==2.14.1+cpu`.

**Source provenance tightened**: the earlier `ci_install.sh` did NOT pass
`--no-deps`, so the CPU index also served torch's transitive reqs (filelock,
typing-extensions, setuptools, sympy, networkx, jinja2, fsspec) — wider than the
comment claimed. Now step 1 = CPU index + `--only-binary=:all:` + `--no-deps`
(torch only); step 2 = PyPI only for the editable project + everything else;
step 3 = fail closed on `pip check`, nvidia-*/triton, non-`+cpu` torch.

**Guard lesson**: string assertions on the script were satisfied by *comments*
that mention the flag. `_code()` strips comments before asserting; use semantic
tokens (`endswith("+cpu")`, `startswith("nvidia-")`, `if cuda:`, `sys.exit(1)`,
`"${CONSTRAINTS}"` count) not bare substrings. Mutation harness
`scripts/ci_torch_mutations.py` kills **10/10**; wired into the `trust-mutations`
CI job (light env: pytest/pytest-asyncio/pydantic/pydantic-settings/structlog/
httpx/numpy/pillow/sqlalchemy/sqlmodel/aiosqlite + `pip install --no-deps -e .`).
NOTE: the guard needs the tests/conftest.py storage chain (sqlalchemy/sqlmodel/
aiosqlite) or the autouse teardown fixture errors.

**Pitfalls learned**:
- Never `git checkout` another branch while a background pytest suite runs — it
  reads the wrong tree and yields bogus failures (11 fake py3.11 failures included
  the new guard tests, which only exist on the 308 branch).
- A `git reset --soft HEAD~1` after a conflict CLEARS `MERGE_HEAD`, so the
  recommit becomes a single-parent commit and loses merge ancestry. Redo the merge
  from scratch instead of "fixing" ancestry.
